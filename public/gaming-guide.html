Bring your game to Amerika.

Makk Social Plus members can publish browser games. Players sign in with their own Social accounts; your game receives its own save data, never their account credentials.

Package your web build

  1. Export a self-contained HTML5/WebAssembly build. Include index.html and every script, style, font, image, audio file and engine data file. Keep original filenames.
  2. ZIP those files. A single enclosing directory is supported. The ZIP and the total extracted files must each be smaller than 1,000,000,000 bytes. Up to 10,000 files. No encrypted archives, symbolic links, hidden files, executable desktop programs or path traversal.
  3. Use the cloud save SDK below, or standard localStorage. The platform restores cloud data before starting classic or module scripts in community games. For frameworks that subscribe to DOM readiness after loading, also handle the amerika-ready event.
  4. Sign in to a Plus account at Amerika Gaming, fill out the submission form, confirm your publishing rights and rules, then upload. Validation finishes before the game appears in the library. My games lets you replace a ZIP, unpublish or delete it.

Supported files: HTML, JavaScript/modules, CSS, JSON, WebAssembly, Godot PCK, images, fonts, audio/video and binary game data. Native executables and server code cannot run. Ten games per creator, approximately 5 GB per creator, subject to available platform storage.

Cloud save SDK

The platform injects window.AmerikaGame. Do not put Social passwords, API keys or account tokens in your game. Saves are private to the signed-in account and the game ID. A replacement upload retains that game ID and its saves, so keep your save format backward-compatible.

async function startGame() {
  await AmerikaGame.ready;
  const progress = await AmerikaGame.load();
  // Restore your game, or begin a new adventure.
  initialize(progress || { level: 1, score: 0 });
}

async function saveCheckpoint(level, score) {
  await AmerikaGame.save({ level, score });
  // The promise resolves only after the server confirms saving.
}

startGame();

The save must be JSON-serializable and fit inside the 1 MB total save envelope, including localStorage and other SDK data. Keep individual saves below 900 KB. Large textures, audio and level packages belong in the game ZIP, not the save.

Standard localStorage is isolated per game and restored per account. Storage writes are synchronized automatically. IndexedDB, third-party cloud saves and arbitrary engine save files are not captured automatically: integrate them through AmerikaGame.load() and save(). The five Amerika originals include a dedicated Godot save-file bridge.

Browser restrictions

Games run in a sandbox without access to Social cookies, session storage, login tokens or other accounts' saves. External network requests, popups, nested frames, top-level navigation, form submission and service workers are blocked. Include your dependencies in the ZIP. Single-threaded WebAssembly works; builds requiring SharedArrayBuffer/cross-origin isolation, native extensions or server-side code are not supported in this player.

Audio, full screen and pointer lock are subject to browser permission and user-gesture rules. Show a start button for games that need audio. Use the player's full-screen button. Make controls and device requirements clear; keyboard games do not become touch games automatically.

Saving responsibly

Save meaningful checkpoints and settings, rather than every animation frame. A server-confirmed revision prevents one device from silently replacing a newer save from another window. A conflict asks the player to reload the latest cloud save. Network problems leave progress marked unsynced; players should keep the page open and wait for “Saved to your account.” Offline or unconfirmed progress is not guaranteed to survive closing a tab.

Publishing rights and rules

You retain your rights in your game. By submitting it, you authorize Cherry Blossom LLC to host its files, deliver and execute them in players' browsers, display your listing, and maintain operational copies while it is published. Your game and assets must be yours or appropriately licensed. Crypto mining, phishing, card fraud/testing, spam, pirated content and illegal content are prohibited. Profanity and lawful viewpoints alone are allowed. Players can report games, and staff can disable them.

Cloud saves are included in account deletion. Deleting a game removes its hosted package and saved progress; unpublishing keeps existing saves while removing public play access. Uploaded packages live on the platform's persistent game storage. Account progress is stored in the backed-up application database; package and infrastructure backup retention can differ.
