# Amerika Studio (Developer Edition): architecture

Goal: turn the laptop into an agentic game-making machine. Four apps where you describe what you want and Claude does it, plus integration with Amerika Agent (OpenClaw-based, already shipped in 3.1.x).

| App | What it is | How it is built (honest) |
|---|---|---|
| **Amerika Render** | Blender with an AI modelling assistant | Upstream **Blender** (GPL-3.0+, Ubuntu `blender` 5.0.1 arm64) + our **`amerika_render` add-on** (chat panel, tools driving `bpy`) + Amerika launcher, splash, theme, own config dir. Not a source fork: no multi-day ARM compile, and upstream updates stay free. "Blender" is a trademark of the Blender Foundation: call ours "Amerika Render, powered by Blender" and ship Blender's GPL notices. |
| **Amerika Engine** | Godot with an AI game assembler | Upstream **Godot** (MIT, Ubuntu `godot` 4.6.3 arm64; official 4.7.2 arm64 zips exist) + **`amerika_engine` editor plugin** (chat dock, project/scene/script tools, "game recipe" assembler) + launcher/branding/templates. |
| **Amerika Sprite** | pixel-art editor with an AI sprite builder | **Original code** (HTML5 canvas app in a WebKitGTK window). We do NOT copy or modify Aseprite: its source is under a proprietary EULA that forbids redistributing modified builds. Aseprite is only a feature reference; read-only import of `.aseprite` files is allowed to implement from the public file-format spec. |
| **AmerikaBox** | desktop chiptune maker with an AI composer | **Fork of BeepBox** (MIT, https://github.com/johnnesky/beepbox; keep its licence and credit) built into a desktop app (WebKitGTK window) + AI panel that writes/edits songs through BeepBox's own song JSON. |

## Shared layer (owner: studio-core)

- **Key**: ONE Anthropic key manager. Stored in the Secret Service (libsecret): attributes `service=amerika-studio name=anthropic`. Each app can use the shared key, or its own override (`name=anthropic-<app>`; apps: render, engine, sprite, box). If the user prefers, a toggle lets Studio reuse the Amerika Agent's key (`service=amerika-agent name=anthropic`). Keys never in files, argv, env of other processes, logs, git, tests (use `sk-ant-test-FAKE`). Entering the key: `amerika-studio key set [--app render] ` (key on stdin only), a GTK dialog (`amerika-studio-keys`), and an "Amerika Studio" page in Amerika Settings.
- **Bridge daemon** `amerika-studio-bridge` (python3 stdlib, systemd --user, loopback `127.0.0.1:18890`, auth with a per-user token in `$XDG_RUNTIME_DIR/amerika/studio-token` mode 0600): `POST /v1/messages` proxies to `https://api.anthropic.com/v1/messages` adding `x-api-key` + `anthropic-version` server-side (apps/plugins never see the key); body validated (model allowlist from `GET /v1/models`: `claude-sonnet-5-5` default, `claude-opus-5-5`, `claude-haiku-5-5`; `max_tokens` cap; size cap; no `stream` in v1); header `X-Amerika-App: render|engine|sprite|box|agent` selects the key; `GET /v1/status` -> `{"key":{"render":bool,...},"models":[...],"version":str}`; metadata-only usage log `~/.local/state/amerika-studio/usage.jsonl` (time, app, model, token counts; never prompts/responses); simple spend guard (daily token budget, configurable, default generous). Plugins call it with only the token (read from the file) — Blender's Python and Godot's `HTTPRequest` can both do that.
- **Tool-use loop lives in each app** (tools must run inside Blender/Godot/the webview). Common prompt/loop helpers: `src/os/studio/amerika_studio/` (Python, used by Blender add-on, by the Sprite/Box Python backends, and by tests); a JS port for the webview apps (Sprite, Box) in `src/os/studio/web/ai-client.js`; GDScript port for Godot in `src/os/engine/.../ai_client.gd`.
- **App control endpoints for Amerika Agent**: each running app opens a loopback JSON-RPC HTTP server (`127.0.0.1:<port>`, token) and publishes `$XDG_RUNTIME_DIR/amerika/studio-<app>.json` = `{"app":"render","url":"http://127.0.0.1:P","token":"..."}` (0600). A single MCP stdio server `amerika-studio-mcp` (owner: studio-core) exposes `render.*`, `engine.*`, `sprite.*`, `box.*` tools by calling those endpoints, launching the app first through its launcher when asked, and is registered in the Amerika Agent OpenClaw config as `mcp.servers.amerika-studio` (patch `src/os/agent/amerika_agent/config.py`; owner: studio-core) plus in `amerika-mcp` risk classes (these tools are `act`; deleting/overwriting files outside a project is never allowed; shell/python execution tools are `critical` → always ask).
- **Hub app** "Amerika Studio" (launcher with four tiles, status, key setup, recent projects) and shared WebKitGTK shell `amerika-studio-webview` for Sprite/Box (owner: studio-core). Look: retro-futurist neon-on-chrome, consistent with AltStack Desktop (`am-*` GTK CSS, same icon style; icons as SVG, installed to hicolor).
- **Project folder**: `~/Studio/{Render,Engine,Sprite,Box}`; every tool confined to the project directory.
- **Safety**: model-generated Python for Blender (`bpy`) and GDScript run inside the apps: show the generated code in the panel, keep undo checkpoints, provide a "Review before run" mode (default ON for `exec`-style tools, OFF for structured tools), a Stop button, and timeouts. No network access from generated code is added by us. Never run generated shell commands.

## Packaging (every owner adds `tools/builders/<name>.py`; do NOT edit build.py)

`build.py` loads `tools/builders/*.py` (`register(b)` returns `{pkg: builder}`; optional `META_DEPENDS`/`META_RECOMMENDS`). Packages: `amerika-studio` (core, bridge, mcp, hub, keys, web shell), `amerika-render` (Depends: `amerika-studio`, `blender`), `amerika-engine` (Depends: `amerika-studio`, `godot`), `amerika-sprite`, `amerika-box`, and meta `amerika-developer` (depends on all four + `git`, `build-essential`-lite tooling, `ffmpeg`, `gimp` optional recommends, `audacity` recommends, `vulkan-tools`, `mesa-utils`) with `Recommends` kept sensible. Version = `b.DE_VERSION`. The developer edition is **opt-in** (not a dependency of `amerika-desktop`).

- Do not push, release or deploy anything.
